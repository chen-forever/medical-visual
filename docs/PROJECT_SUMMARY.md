# 岐黄 · 状态：总体规划与项目总结

> 项目：中医数字人体状态可视化系统 / Qihuang State  
> 当前版本：`v0.2.0`  
> 仓库：https://github.com/chen-forever/medical-visual  
> 文档更新：2026-11-15

## 0. 一页结论

**作为视觉演示：基本完成。**  
**作为医生日常使用的诊所工具：完成约一半。**  
**作为可公开上线的产品：还差较长的路。**

当前 `v0.2.0` 已经具备：

- 十页业务闭环；
- 3D 数字人体；
- DeepSeek 真实证型分析；
- SQLite 病例、分析、药方、报告、审计；
- 单医生登录；
- 病位自动保存；
- 7 / 14 / 30 天人体变化；
- 可打印 A4 报告；
- GitHub 可复现安装；
- 24 个服务端测试。

当前最关键的缺口不是“页面不够多”，而是：

1. 多用户/RBAC 和诊所级权限；
2. 报告分享与正式 PDF；
3. 分析历史 UI；
4. 中医内容专业审核；
5. 备份、监控、云端部署与合规。

## 1. 项目定位

### 1.1 一句话

把中医“望、闻、问、切”与调理方案，转译成**医生讲得清、患者看得懂**的人体状态图层与时间变化模拟。

### 1.2 它是什么

- 诊室沟通工具；
- 中医证型与病位的可视化解释器；
- 医生输入、系统辅助整理、医生最终确认的工具；
- 7 / 14 / 30 天状态的示意推演。

### 1.3 它不是什么

- 不是诊断系统；
- 不自动开方；
- 不生成剂量建议；
- 不承诺疗效；
- 不是患者个体扫描；
- 不替代面诊、检验、影像或医生决策；
- 不做本地大模型。

### 1.4 三条产品红线

1. 不把证型候选写成确诊结论；
2. 不让模型自动生成处方或剂量；
3. 不把示意动画包装成疗效预测。

## 3. 已完成工作

### 3.1 十页闭环

| 路由 | 页面 |
|---|---|
| `#/home` | 工作台、最近病例 |
| `#/patient` | 患者信息与望闻问切 |
| `#/analysis` | DeepSeek 证型分析、证据、红旗筛查 |
| `#/body` | 数字人体 |
| `#/inside` | 内部观察 |
| `#/lesion` | 病位定位与自动保存 |
| `#/state` | 当前状态与粒子 |
| `#/formula` | 药方记录 |
| `#/timeline` | 7 / 14 / 30 天变化 |
| `#/report` | A4 报告与审计记录 |

### 3.2 3D 数字人体

- Human Atlas / BodyParts3D 4.0；
- CC BY 4.0；
- 压缩为约 **10.37 MB** 单分块；
- 约 **64.7 万三角形**；
- 默认锁定旋转，只保留缩放、图层、复位；
- 体表、骨骼、肌肉基础层；
- 胃、胆、小肠、大肠、膀胱、心、肺、肝、脾、肾 10 个器官层；
- 器官点选、中医归属、经络说明；
- 病位标记、连线、粒子、时间轴动画；
- 不是患者个体扫描，是成年男性参考解剖；
- 胃壁四层是示意色带，不是真实四层网格。

证据：

- `app/public/models/human-atlas/COMPRESSION.md`
- `app/public/models/human-atlas/ATTRIBUTION.md`
- `npm run verify:assets`

### 3.3 DeepSeek 分析

- 服务端代理，Key 不进入浏览器；
- `deepseek-flash`；
- JSON Output；
- 关闭 thinking；
- 超时与一次重试；
- 红旗规则优先于模型；
- 真实 API 联调通过；
- 没有 Key 时保留演示分析，不白屏。

### 3.4 本地后端

- Node 24 内置 `http`；
- Node 24 内置 `node:sqlite`；
- 无 ORM、无额外运行时依赖；
- 单进程同时提供前端和 API；
- 数据表：
  - `cases`
  - `analyses`
  - `formulas`
  - `reports`
  - `events`

数据库默认位置：

```text
server/data/qihuang.sqlite
```

### 3.5 登录、审计、病位保存

- 单医生访问密码；
- HMAC 签名 HttpOnly Cookie；
- 12 小时会话；
- 登录限流；
- 病例版本冲突返回 409；
- 病位独立 `lesionVersion`；
- 修改病位不会让证型分析失效；
- 病位自动保存；
- 报告页显示本病例操作记录；
- 固定密码命令：`npm run auth:set-password`。

## 4. 未完成与缺口

### 4.1 产品/临床

| 缺口 | 影响 |
|---|---|
| 多用户/RBAC | 只能单医生使用，不能分角色管理 |
| 分析历史 UI | 数据库有记录，界面没有完整对比页 |
| 病例搜索/归档 | 病例多了以后不好找 |
| 复诊/随访 | 不能看同一患者多次就诊变化 |
| 报告分享/撤销 | 只能本机打印 |
| 服务端 PDF | 依赖浏览器打印 |
| 舌象/面色/影像上传 | 缺少真实四诊素材 |
| 方剂库/禁忌 | 药方只是自由输入记录 |
| 中医内容审核 | 证型、经络、药方仍需专业确认 |
| 女性/不同体型模型 | 当前只有成年男性参考 |
| 真实胃壁分层 | 当前是示意色带 |
| 经络走行 | 仍需专业审核 |

### 4.2 技术

- SQLite 只适合单实例；
- 没有数据库迁移框架；
- 没有自动备份/恢复；
- 没有独立审计后台；
- 会话没有自动续期；
- 没有 CSRF Token；
- 限流只在内存，重启丢失；
- 没有结构化日志/监控/错误追踪；
- 前端 bundle 约 959 KB，gzip 约 258 KB；
- Three.js 未按需加载；
- 没有前端单元测试/E2E；
- 移动端和无障碍未系统验收；
- WebGL 低性能设备降级不完整。

### 4.3 部署与运维

- 没有云端部署；
- 没有 HTTPS/域名；
- 国内上线没有 ICP；
- 没有备份、监控、告警；
- 没有发布/回滚流程；
- CI 状态未从 GitHub API 确认（未登录 API 触发限流）。

### 4.4 安全与合规

- 密码以明文保存在本地 `.env.local`；
- 数据库未加密；
- 没有隐私政策/知情同意；
- 没有真实患者数据治理流程；
- 仓库当前是公开的；
- 代码没有单独开源许可证；
- 带第三方水印的参考图未提交。

## 8. 风险与假设

- AI 输出可能不稳定，需要医生复核；
- 中医内容有专业审核责任；
- 3D 是参考解剖，不是个体；
- 7 / 14 / 30 天是示意模拟；
- SQLite 不适合多实例；
- 本地密码和数据库需要保护；
- 公开仓库涉及版权、许可证和医学表述；
- 真实患者数据有隐私与合规要求；
- 依赖 Node 24 和 DeepSeek API；
- 不能把演示效果当成临床疗效证据。

## 10. 下一步建议

优先级最高的是：

1. **多用户/RBAC + 审计查看 + 自动备份**；
2. **分析历史 + 报告分享/PDF**；

在这之前，建议先用当前 `v0.2.0` 让医生完整走 3–5 个真实病例，记录：

- 哪些页面最常用；

- 报告是否真的能用于沟通；
- 7 / 14 / 30 天动画是否帮助理解；
- 哪些字段是医生不想填的。
